# Concert Radar

Личная афиша концертов любимых артистов в странах Шенгена, ОАЭ (Дубай и Абу-Даби), Саудовской Аравии и Омане.

- **Приложение:** https://nadyaomeroglu.github.io/concert-radar/ *(заработает после Фазы 6)*
- **Обновление:** автоматически каждый день в 06:17 UTC (около 10:15 по Дубаю)
- **Уведомления:** Telegram-бот присылает сводку после каждого обновления

> Документ в работе. Разделы, помеченные *«будет заполнено»*, появятся по мере готовности проекта.

## Как это устроено

| Часть | Где находится | Что делает |
|---|---|---|
| Список артистов | `config/artists.yaml` | Кого отслеживать |
| Список регионов | `config/regions.yaml` | В каких странах и городах показывать концерты |
| Сборщик | папка `collector/` | Программа, которая собирает концерты из источников |
| Автоматизация | папка `.github/workflows/` | `collect.yml` — ежедневная проверка, `add-artist.yml` — добавить артиста, `pages.yml` — публикация сайта, `tests.yml` — проверки кода |
| Приложение | папка `docs/` | Сайт, который вы открываете на телефоне |
| Данные | `docs/data/` | Найденные концерты, изменения, служебная информация |

Сервера нет и платить ничего не нужно: сборщик запускает GitHub Actions, а сайт показывает GitHub Pages.

## Как установить на телефон

Приложение ставится на экран «Домой» и открывается как обычное приложение, без адресной строки.
Интерфейс приложения — на английском.

**iPhone** (только через Safari):
1. Откройте в Safari ссылку https://nadyaomeroglu.github.io/concert-radar/
2. Нажмите кнопку **«Поделиться»** (квадрат со стрелкой вверх) внизу экрана.
3. Пролистайте меню и выберите **«На экран "Домой"»**.
4. Нажмите **«Добавить»** в правом верхнем углу. Появится иконка с микрофоном.

**Android** (через Chrome):
1. Откройте в Chrome ту же ссылку.
2. Нажмите **⋮** (три точки) в правом верхнем углу.
3. Выберите **«Установить приложение»** (или **«Добавить на главный экран»**).
4. Подтвердите кнопкой **«Установить»**.

### Что есть в приложении

| Вкладка | Что показывает |
|---|---|
| **Upcoming** | Афиша по датам. Поиск, фильтры (артист, страна, город, месяц), быстрые кнопки «New only» и «On sale» |
| **Artists** | Все ваши артисты и сколько у каждого концертов; нажмите на артиста — увидите только его концерты |
| **What’s new** | Что изменилось при последнем обновлении: новые концерты, переносы, скорый старт продаж |
| **About** | Когда было последнее обновление, работают ли источники, светлая/тёмная тема |

На каждой карточке концерта:
- **Buy tickets** — переход на страницу продажи (если источников несколько — по кнопке на каждый);
- 📅 — добавить концерт в календарь телефона;
- ⤴ — поделиться концертом.

Бейджи: **New** — появился после вашего прошлого визита, **Changed** — что-то изменилось
(дата, площадка, статус), **On sale 25 Oct, 10:00** — когда стартуют продажи, **Cancelled** / **Postponed** — отменён / перенесён.

Без интернета приложение показывает последнюю сохранённую афишу (вверху появится «Offline · saved data»).

## Как добавить артиста

### Способ 1. Кнопкой с телефона (проще всего)

Нужно приложение **GitHub** (App Store / Google Play), вход под своим логином.

1. Откройте репозиторий **concert-radar**.
2. Нажмите **Actions** (если не видно — пролистайте вниз до раздела с действиями или нажмите **More**).
3. Выберите **Add artist**.
4. Нажмите **Run workflow**.
5. В поле **Artist or band name** впишите имя артиста так, как оно пишется на афишах (например, `Florence + The Machine`).
6. Поле **Official tour page** — по желанию: ссылка на страницу туров на официальном сайте (начинается с `https://`). Можно оставить пустым.
7. Нажмите **Run workflow** ещё раз.

Через 1–2 минуты артист появится в списке, его концерты — в приложении, а в Telegram придёт сообщение, если концерты нашлись.
Если артист уже есть в списке, запуск остановится с красным значком и пояснением «already in the list» — это нормально.

С компьютера то же самое: github.com → репозиторий → вкладка **Actions** → слева **Add artist** → справа кнопка **Run workflow**.

### Способ 2. Отредактировать список на github.com

1. Откройте файл `config/artists.yaml` в репозитории.
2. Нажмите на значок карандаша ✏️ (**Edit this file**) справа вверху.
3. Перейдите в самый конец файла и добавьте блок — **с теми же отступами** (два пробела перед `-`, четыре перед остальными строками):
   ```yaml
     - name: "Florence + The Machine"
       aliases: ["Florence + The Machine", "Florence and the Machine"]
       official_tour_url: null
       ticketmaster_id: null
       active: true
   ```
   - `aliases` — другие варианты написания имени (через запятую, каждый в кавычках).
   - `official_tour_url` — ссылка на страницу туров в кавычках или `null`, если нет.
   - `ticketmaster_id` — оставьте `null`, заполнится само.
4. Нажмите зелёную кнопку **Commit changes…**, затем ещё раз **Commit changes**.

Артист начнёт отслеживаться со следующей ежедневной проверки (или запустите сбор вручную — см. ниже).

**Временно не отслеживать артиста:** поменяйте у него `active: true` на `active: false`.

## Как запустить сбор вручную

1. Приложение GitHub (или github.com) → репозиторий **concert-radar** → **Actions**.
2. Выберите **Collect concerts**.
3. Нажмите **Run workflow**.
4. Поле **Only this artist** оставьте пустым, чтобы проверить всех (или впишите одно имя из списка).
5. Нажмите **Run workflow**.

Проверка всех артистов занимает несколько минут. Зелёная галочка — всё прошло, красный крестик — что-то пошло не так (данные при этом не теряются).

## Как поменять список стран и городов

Откройте файл `config/regions.yaml` на github.com, нажмите на значок карандаша (✏️ «Edit this file») и измените список.

- **Добавить страну целиком** (например, Великобританию): допишите её код в строку `extra_countries`, например `extra_countries: ["SA", "OM", "GB"]`.
- **Важно:** каждый код страны пишите **в кавычках**. Без кавычек код Норвегии `NO` прочитается как «нет».

- **Убрать страну:** удалите её код из списка вместе с запятой.
- **Добавить город в ОАЭ** (например, Шарджу): в разделе `cities` → `"AE"` добавьте по образцу
  ```yaml
      - name: Sharjah
        aliases: [Sharjah]
  ```
- После правки нажмите **Commit changes…** → **Commit changes**. Изменения применятся со следующей проверки.

## Как поменять расписание

Сейчас проверка идёт **каждый день в 06:17 UTC** (10:17 по Дубаю).

1. Откройте файл `.github/workflows/collect.yml`, нажмите ✏️.
2. Найдите строку `- cron: "17 6 * * *"`.
3. Замените значение в кавычках на одно из готовых (время всегда **UTC**, Дубай = UTC + 4 часа):

| Как часто | Что вписать |
|---|---|
| Каждый день в 10:17 по Дубаю (сейчас) | `"17 6 * * *"` |
| Каждый день в 08:17 по Дубаю | `"17 4 * * *"` |
| Два раза в день, 10:17 и 22:17 по Дубаю | `"17 6,18 * * *"` |
| Каждые 6 часов | `"17 */6 * * *"` |
| По понедельникам и пятницам | `"17 6 * * 1,5"` |

4. Нажмите **Commit changes…** → **Commit changes**.

Чаще, чем раз в час, ставить не стоит. Любой из вариантов бесплатный.

## Сообщения в Telegram

Бот пишет **на английском** после ежедневной проверки, но только если есть что сказать:

| Раздел сообщения | Что значит |
|---|---|
| **New concerts** | Появились новые концерты (если известна дата старта продаж — она указана сразу) |
| **Changes** | У концерта поменялась дата, город, площадка, время или статус (было → стало) |
| **No longer listed** | Концерт пропал из всех источников два дня подряд |
| **🎟 Tickets go on sale soon** | Продажи стартуют сегодня или завтра. Напоминание приходит **один раз** |
| **📅 Sale dates announced** | Для уже известного концерта объявили дату старта продаж (или перенесли её) |
| **✅ Checked — no new concerts** | Приходит **по понедельникам**, если за день ничего не случилось — знак, что система жива |

Время везде указано **по Дубаю**.

## Что делать, если пришло сообщение об ошибке

| Сообщение | Что это значит | Что делать |
|---|---|---|
| ⚠️ **Platinumlist is unavailable** | Сайт не пустил сборщик (защита от роботов) или не ответил | Ничего. Остальные источники работают. Если повторяется неделями — напишите Claude, он предложит альтернативу |
| ⚠️ **Ticketmaster is unavailable: … key** | Ключ Ticketmaster не задан или перестал работать | Проверьте секрет `TICKETMASTER_API_KEY` (см. «Ключи и секреты») |
| ⚠️ **Ticketmaster is unavailable: quota** | Превышен дневной лимит запросов | Ничего, завтра лимит обнулится |
| ⚠️ **…: errors for N artist(s)** | Часть артистов не обработалась (временная ошибка) | Ничего, если не повторяется. Подробности — во вкладке **About** приложения |
| ✅ **… works again** | Источник снова работает | Ничего |
| ❓ **Several artists with the same name** | На Ticketmaster несколько артистов с таким именем | Откройте ссылки, найдите нужного и впишите его `id` в `config/artists.yaml` в поле `ticketmaster_id` (или попросите Claude) |
| ⛔ **Nothing could be collected this time** | Не сработал ни один источник | Приложение показывает прежние данные. Если повторится 2–3 дня подряд — напишите Claude |

Ошибки не сообщаются каждый день: бот пишет, когда источник **сломался** и когда **починился**, а по понедельникам напоминает о том, что всё ещё не работает.

Если сообщения **перестали приходить совсем** (даже по понедельникам) — см. раздел «Если GitHub отключил расписание».

## Если GitHub отключил расписание

В публичных репозиториях GitHub автоматически выключает расписание, если **60 дней** в репозитории не было активности.
Чтобы этого не случилось, каждая проверка сохраняет свежие данные (это новая запись в репозитории) и отдельно
«продлевает» расписание через GitHub API. Если всё же отключилось — признак: сообщения в Telegram перестали приходить
даже по понедельникам.

Как включить снова:
1. github.com → репозиторий **concert-radar** → вкладка **Actions**.
2. Слева выберите **Collect concerts**.
3. Вверху будет жёлтая плашка «This scheduled workflow is disabled…». Нажмите **Enable workflow**.
4. Для проверки нажмите **Run workflow** (см. «Как запустить сбор вручную»).

Ещё GitHub сам присылает письмо на почту, если запуск по расписанию завершился ошибкой.

## Ключи и секреты

Ключи хранятся **только** в зашифрованном хранилище GitHub. В коде, в логах и на сайте их нет.

| Имя секрета | Что это | Где взять |
|---|---|---|
| `TICKETMASTER_API_KEY` | Ключ Ticketmaster Discovery API | developer.ticketmaster.com → My Apps → **Consumer Key** |
| `TELEGRAM_BOT_TOKEN` | Токен бота | @BotFather → `/mybots` → ваш бот → **API Token** |
| `TELEGRAM_CHAT_ID` | Номер вашего чата с ботом | см. ниже |

**Как добавить или заменить секрет:**
1. github.com → репозиторий **concert-radar** → **Settings** (вкладка с шестерёнкой).
2. Слева: **Secrets and variables** → **Actions**.
3. Нажмите **New repository secret** (для замены — карандаш ✏️ рядом с существующим).
4. **Name** — имя из таблицы, точно как написано. **Secret** — само значение, без пробелов и кавычек.
5. Нажмите **Add secret**.

**Как узнать chat_id:**
1. Напишите своему боту в Telegram `/start`.
2. Откройте в браузере `https://api.telegram.org/botТОКЕН/getUpdates`, подставив токен вместо слова `ТОКЕН` (слово `bot` оставьте).
3. Найдите `"chat":{"id":` — число после него и есть chat_id. Если страница пустая (`"result":[]`), напишите боту ещё раз и обновите страницу.

## Как включён сайт (GitHub Pages)

Settings → **Pages** → **Source: GitHub Actions**. Сайт публикуется автоматически после каждой проверки
процессом **Publish site** — ничего нажимать не нужно.

## Источники данных

| Источник | Регион | Статус |
|---|---|---|
| Ticketmaster Discovery API | Европа | будет подключён на Фазе 2 |
| Platinumlist | ОАЭ, страны Залива | будет проверен на Фазе 2 |
| Официальные сайты артистов | все | будет подключён на Фазе 2 |

Данные о событиях принадлежат их источникам. Приложение хранит только факты (дата, город, площадка) и ссылки на страницы продажи билетов.
